# 艾泽拉斯星命罗盘 · 魔兽世界职业测试

> 结合「职业背景 + 星座学 + 性格维度」的粉丝向职业测试 Web 应用。
> 开始前先**点选你的星座**：每局从 **96 条题库**中按星座加权抽取 18 条陈述题（五档赞同度作答），由「你的星座 + 你的作答」两套星图共同推演出**主职业**与**副职业**；支持**经典怀旧服**（9 职业）与**正式服**（13 职业）双模式——题组局局不同，分享链接可完整复现。

本页面为粉丝向同人作品，与 Blizzard Entertainment 无关联；页面未使用任何官方美术与字体素材，全部图形为原创程序化绘制（CSS / SVG）。测试结果仅供娱乐参考。

---

## 快速开始

零依赖、零构建。任选一种方式启动：

```bash
# 方式一：内置静态服务器（推荐）
cd wow-class-quiz
node scripts/serve.mjs          # 或 npm run serve
# 打开 http://127.0.0.1:5173/

# 方式二：任意静态服务器
python3 -m http.server 5173
```

> ⚠️ 必须通过 HTTP 访问（不能用 file:// 直接打开 index.html），因为应用使用了 ES Modules。

## 运行测试与验证

```bash
npm run verify          # 引擎批量验证：题库结构 / 采样器 / 确定性 / 双模式共 4 万次随机轰炸 / 分布健康度 / 边界……（Node，零依赖）
npm run verify:contrast # 关键配色对比度检查（WCAG，10 项）
npm run verify:exports  # 台账导出功能验证（无头 Chrome + CDP 下载校验，12 项）
npm run e2e             # 无头 Chrome 全流程 E2E（需本机 Chrome；会自检 66 项）
node scripts/shot.mjs   # 重新生成 screenshots/ 下的交付级截图（需先启动 serve）
```

## 评分引擎说明

总分（0-100）= **35%** 职业背景直连 + **45%** 性格六维契合 + **20%** 星辰修正。

1. **职业背景直连**：每局先点选星座，随后按星座加权从三池抽取 18 条陈述（每池至少 3 条与星座共鸣的条目）。每条携带若干职业的"共鸣权重"。五档作答按符号加权（赞同加分、反对减分：非常＝±1.0、普通＝±0.5、中立＝0）；得分先除以该职业在本局题组的"机会覆盖率"再池内归一化——保证各职业公平竞争。
2. **性格六维契合**：勇气 / 谋略 / 慈悲 / 求知 / 自由 / 信念。用户向量与职业向量做 z-score 标准化后计算余弦相似度，比较"性格形状"而非单项峰值。
3. **星辰修正**：你选择的星座与答题轨迹推演出的共鸣星座两套星图加权合并（选择星座 ×1.0 + 推演星座 ×0.6；未选择时按纯推演口径），职业侧加成按覆盖率归一。
4. **主职业** = 全池总分最高；**副职业** = 次高且与主职业"主定位不同"的职业（+3 互补加成），保证主副不重复、定位互补。

确定性保证：题组由「模式 + 星座 + 种子」确定性生成，评分无随机数、无时间依赖；同一题组与作答任何时刻重算，结果与得分明细完全一致。分享链接把「星座 + 题组种子 + 18 项作答」编码进 URL（v3 含校验位；v2 旧码仍可复现），无需服务端即可完整复现同一次测试。

> 当前引擎版本 **3.0.0**（题库 3.0）：开始前点选星座，题组按星座加权抽取（每池 ≥3 条星座题）；计分升级为「选择星座 ×1.0 + 作答推演 ×0.6」双星图锚定；结果页新增同频度解读；分享链接升级为 v3。

## 常见维护任务

### 1. 新增 / 调整题目

编辑 `src/data/questions.js`，按池新增条目即可（每池建议保持 ≥ 26 条，保证抽样空间）：

```js
{
  id: 'L33',                          // 唯一 ID（L/Z/H 前缀 + 序号）
  kind: 'lore',                       // 'lore' 命运抉择 | 'zodiac' 星辰低语 | 'heart' 本心试炼
  text: '一句第一人称陈述——玩家会为它选择五档赞同度。',
  // tags: ['retail'],               // 可选：仅正式服收录；'classic' 则仅怀旧服收录
  dims:    { courage: 2, faith: 1 },      // 性格维度加权（主加值 2 / 次加值 1）
  classes: { warrior: 2, paladin: 1 },    // 职业直连加权
  zodiac:  { aries: 2, leo: 1 },          // 星座倾向加权
}
```

规则：
- 数值建议主加值 2 / 次加值 1，单条至少覆盖两类权重；文案不得出现直指职业/专精的词汇（`BANNED_WORDS` 会在 verify 中扫描）；
- 维度 ID 见 `classes.js` 的 `DIMENSIONS`，职业 ID 见 `CLASSES`，星座 ID 见 `zodiac.js`；
- 增删题目后**必须**运行 `npm run verify`——它会重新检查分布健康度（若某职业胜率异常，用 `node scripts/diagnose-balance.mjs` 定位原因）。

### 2. 调整权重与公式

- 三类权重比例：`src/engine/scoring.js` 中 `WEIGHTS = { base: 0.35, personal: 0.45, zodiac: 0.2 }`。
- 副职业互补加成：`SECONDARY_COMPLEMENT_BONUS`（默认 3）。
- 职业性格模板：`src/data/classes.js` 每个职业的 `dims`（六维 1-10）。
- 星座修正表：`src/data/zodiac.js` 每个星座的 `classBias`（该星座对某职业的加成）。

改完全量跑 `npm run verify`（含双模式随机轰炸分布统计）；偏斜时用 `node scripts/diagnose-balance.mjs` 分解定位。

### 3. 扩展职业池 / 模式

- 新职业：在 `src/data/classes.js` 的 `CLASSES` 中加入完整字段（dims / roles / modes / color / 文案）。若仅属于正式服，不写 `modes.classic` 即可被怀旧服池自动排除。
- 新模式：在 `MODES` 中声明，并在 `classPool()` 中给出筛选规则；同步检查 `computeResult` 的池过滤逻辑与分享编码的模式位。
- 记住同步更新：题库中该职业的直连权重（否则 coverage 归一会让它几乎没有得分机会）、`zodiac.js` 的相关 bias。

### 4. 新增一种结果解读维度

1. 在 `src/data/classes.js` 的 `DIMENSIONS` 与每个职业的 `dims` 中加入新维度（1-10）；
2. 在 `src/ui/copy.js` 的 `DIM_META` 填入名称与高低分文案；
3. 在 `src/ui/app.js` 的 `DIM_ORDER` / `DIM_COLORS` 登记颜色与展示顺序；
4. 陈述权重中即可使用该维度。运行 verify 确认分布未失衡。

## 数据与隐私

- 作答进度、历史台账全部保存在**浏览器本地**（localStorage），不上传服务器；
- 历史记录最多保留 100 条，支持单条导出（JSON）、整表导出（JSON / CSV）与清空；
- 浏览器不支持本地存储时自动降级为内存模式（有提示），功能不中断。

## 已知边界

- 题组按规则随机抽取：同一模式两次开局的题组与顺序都不同；分享链接内嵌题组种子，可完整复现某一次的结果；
- 星座解读按答题轨迹推演，非出生星座；不采集任何个人信息；
- 「信念（faith）」维度为宽口径：涵括信仰、坚守、认真与尽责（个别题目按此口径计分）；
- 经典怀旧服的专精列表取自经典旧世（如潜行者「刺杀/战斗/敏锐」），与正式服译名（奇袭/狂徒/敏锐）不同属正常；
- 建议使用现代浏览器（Chrome / Edge / Safari / Firefox 最新版）。
